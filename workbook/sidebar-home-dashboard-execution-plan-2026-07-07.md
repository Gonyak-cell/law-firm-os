## 1. 배경·문제 [직접 확인]

현재 Home 사이드바의 "대시보드/메시지/승인 요청/전자 계약"은 글로벌 유틸리티 뷰로 점프하는 링크다:

- [Shell.jsx:344-359](../apps/web/src/components/Shell.jsx) `sidebarMeta.home.actions` — `대시보드→view:"reports"`, `메시지→view:"messages"`, `승인 요청→view:"requests"`, `전자 계약→view:"esign"`.
- 글로벌 유틸리티 뷰에 진입하면 [Shell.jsx:422-435](../apps/web/src/components/Shell.jsx) `globalSubnav`가 사이드바 전체를 해당 유틸리티의 하위 메뉴로 교체하고, 워크스페이스 타이틀도 "보고서/요청함" 등으로 바뀐다 ([Shell.jsx:561](../apps/web/src/components/Shell.jsx)).
- 상단 제품 축([nav.js](../apps/web/src/data/nav.js): Home/Client/Matter/People/Vault/Portal)에는 이 유틸리티 뷰들이 없으므로, 진입 순간 **축 하이라이트도 사라져** 사용자가 전역 좌표를 잃는다.

리서치 결론: 조사한 20여 개 엔터프라이즈 SaaS·리걸테크·한국 그룹웨어 어디에도 이 동작은 없다(안티패턴 #1 "사이드바 하이재킹"). 사이드바 전면 교체는 Settings/Admin 모드 전환에만, 그것도 복귀 앵커와 함께만 허용된다.

## 3. 내비게이션 불변식 (전 축 공통, 명문화)

> **NAV-01 (글로벌 좌표)**: 상단 제품 축이 유일한 L1 글로벌 좌표다. 어떤 클릭도 축 선택 하이라이트를 잃게 하지 않는다. 모든 화면에서 정확히 하나의 축이 active다.
>
> **NAV-02 (사이드바 계약)**: 좌측 사이드바 = 현재 축의 로컬 내비게이션. **사이드바 교체 트리거는 축 전환뿐이다.** 사이드바 항목 클릭은 콘텐츠 영역만 전환한다.
>
> **NAV-03 (클릭 문법)**: 사이드바에서 1클릭 = 콘텐츠 전환, 셰브론 = 제자리 그룹 확장/축소. 같은 제스처가 화면마다 다른 결과를 내지 않는다.
>
> **NAV-04 (배지 규약)**: 행동 필요 = 숫자 카운트(승인·메시지), 정보성 = 점(dot, 알림). 감소 규칙 명세 필수 — 승인 배지는 결재 처리 시, 메시지 배지는 해당 스레드 열람 시, 알림 dot은 드로어 열람 시 감소. 상단 아이콘 클릭은 **사이드바를 건드리지 않는 오버레이 드로어**를 연다(기존 알림 드로어 패턴 재사용).
>
> **NAV-05 (모드 전환 예외)**: 사이드바 전면 교체는 설정·데이터 가져오기 진입에만 허용하며 3조건을 모두 충족해야 한다 — (1) 상단 바 유지 (2) 사이드바 최상단 '← 업무로 돌아가기' 앵커(직전 라우트 복귀) (3) 더 깊은 계층으로의 진입일 것. 일상 기능은 이 예외를 쓸 수 없다.
>
> **NAV-06 (딥링크 규약)**: 위젯 '전체 보기' = Home 축 내 라우트(사이드바 보존). 위젯 개별 항목 클릭 = 원 도메인 축으로 딥링크하며 축 하이라이트가 목적지 축으로 갱신된다.

## 4. IA 스펙 — 라우트 재매핑

### 4.1 Home 사이드바 최종 구성
```
[워크스페이스 카드: Home]
  대시보드            → home # home-dashboard   (기본, 첫 항목)
  메시지 (n)          → home # home-messages
  승인 요청 (n)       → home # home-requests
  전자 계약           → home # home-esign
  회사 현황 [권한]     → home # home-company     (O-03 권한 게이트)
[시스템]
  데이터 가져오기 [모드 ↗]
  설정 [모드 ↗]
```
`최근작업(home-recent)` 항목은 제거하고 콘텐츠를 대시보드에 흡수한다(§5.3). `알림`은 사이드바에서 제거하고 상단 드로어로 일원화한다(NAV-04).

### 4.2 라우트 재매핑 표

| 현재 라우트 | 신규 라우트 | 처리 |
|---|---|---|
| `view=home` (기본 home-recent) | `view=home#home-dashboard` | 기본 랜딩 교체 |
| `view=reports#reports-home-dashboard` | `view=home#home-dashboard` | redirect |
| `view=messages#*` (5개 섹션) | `view=home#home-messages` + 페이지 내 탭(전송/자동화/템플릿/공지/Matter 대화) | redirect + 탭 매핑 |
| `view=requests#*` (8개 섹션) | `view=home#home-requests` + 페이지 내 탭(받은/보낸) + 유형 필터(휴가·비용·증명서·근무기록·커스텀·강제) | redirect + 필터 매핑 |
| `view=esign#*` | `view=home#home-esign` + 페이지 내 탭 | redirect |
| `view=reports#reports-*` (people/client/matter 분석) | `view=home#home-company` 하위 탭 | redirect, O-03 권한 |
| `view=notifications#*` | 상단 알림 드로어 (라우트 제거) | redirect → home + 드로어 오픈 |
| `view=settings#*`, `view=data-import#*` | 유지 (모드 전환 예외) + '← 업무로 돌아가기' 앵커 추가 | NAV-05 적용 |
| 기존 legacy 라우트 (`globalUtilities.js`의 legacyRoutes) | 최종 목적지로 2-hop 해소 | `resolveGlobalShortcut` 확장 |

**하위 호환**: 기존 URL(북마크·테스트·데스크톱 딥링크)은 전부 위 표의 신규 라우트로 리다이렉트한다. [App.jsx:74-78](../apps/web/src/App.jsx) `resolveRoute`/`resolveGlobalShortcut`에 재매핑 레이어를 추가하고, `globalUtilityViewIds`를 routable에서 제거하는 대신 redirect 전용으로 남긴다.

### 4.3 구현 앵커 [직접 확인]
- `sidebarMeta` / `subnav` / `globalSubnav`: [Shell.jsx:344-560](../apps/web/src/components/Shell.jsx) — home 섹션형 항목으로 재정의, `data-context-sidebar`는 항상 축 ID.
- 축 전환 로직 분리(D-01 진화 예약): `navigateToView`([App.jsx:96-103](../apps/web/src/App.jsx))에서 "축 결정"과 "레이아웃 렌더"를 분리한 `resolveAxis(view)` 헬퍼로 추출 — 향후 좌측 레일 전환 시 이 함수만 교체.

## 5. Home 대시보드 스펙

### 5.1 성격·레이아웃
운영형 triage 화면 — "오늘 무엇을 해야 하는가"에 답한다. 판단은 홈, 처리는 전용 뷰. 고정 그리드(v1) 2존:

```
┌ 승인 대기 (1fr) ┬ 오늘 To Do (1fr) ┬ 캘린더(실제 달력, D-15) ┐
├ 뉴스레터·공지 (2열 풀폭) ─────────┤ 시스템 상태 (레일 하단 고정) │
└──────────────────────────┴──────────────────────┘
```

CSS Grid `grid-template-areas: "appr todo rail" / "feed feed rail"` — 우측 레일(348px)이 두 행을 스팬하고 캘린더 카드가 `flex:1`로 잔여 높이를 흡수해 **모든 카드의 상·하단 끝선이 그리드로 정렬**된다(카드별 개별 높이 금지). 승인 대기·오늘 To Do는 리스트 영역 `flex:1`로 동일 높이를 유지한다. 카드 앵커 통일: 제목+건수 배지=좌상단, '전체 보기'=우상단, 리스트=본문, 인라인 액션=행 우측. 위젯 총량 상한 8. 게이지·파이·도넛 금지, 큰 숫자+리스트만.

### 5.2 위젯 명세

**W-01 승인 대기** (본문 좌상단)
- 데이터: 액션 인박스 `type=approval`, 대상 = 내가 현재 결재 차례인 전 유형(D-09). 정렬: 요청일 오래된 순. 미리보기 4건.
- 탭: 받은 요청(기본) / 보낸 요청(내가 올린 건의 진행 상태).
- 인라인 액션: O-04 저위험 유형만 [승인][반려] — 처리 시 확인 토스트+실행 취소 5초, 감사 로그 필수. 문서 결재 등은 [열기]로 상세 진입.
- 배지 감소: 결재 처리 시 위젯 배지·사이드바 카운트·상단 아이콘 카운트가 **동일 소스에서 동시** 감소.
- 빈 상태: "처리할 승인이 없습니다 — 모두 완료했습니다" (0건=정상 문구).
- 권한 게이팅: 승인 권한 없는 역할에는 '받은 요청' 탭 대신 '보낸 요청'만 노출.

**W-02 오늘 To Do** (본문 우상단)
- 데이터: 액션 인박스 `type=task & assignee=me & status=open`. **업무 태스크만**(사건 할 일). 정렬: 지연(D+n, 적색) → 오늘(주황) → 마감 임박(중립). 미리보기 5건 + 헤더에 "지연 n · 오늘 n" 요약 배지.
- 인라인 액션: 체크 = 즉시 완료 처리(실행 취소 5초). 항목 클릭 = 해당 사건 할 일로 딥링크(NAV-06).
- 빈 상태: 태스크 0건이면 "오늘 마감 업무가 없습니다" / 온보딩 상태면 "첫 할 일 만들기 →" CTA 구분.

**W-03 캘린더** (우측 레일 최상단, D-15: **실제 월간 달력**)
- 형태: 월간 그리드 달력(일요일 시작, 월 전환 ‹ ›). 일정 있는 날 = 점 표시(일반=녹색, 기한=적색), 오늘 = 하이라이트, 일요일 = 적색. 달력 아래에 선택일(기본: 오늘) 일정 목록 + 임박 기한 1건.
- 데이터: 통합 아젠다 — 사건 기일·회의(matter-calendar) + 외부 일정 + 부재 일정. 월 단위 로드(`/home/agenda?from=월초&to=월말`), 점 표시는 일자별 집계.
- 인터랙션: 날짜 클릭 → 아래 일정 목록이 해당 일로 전환(위젯 내에서 처리, 내비 이동 없음). 일정 항목 클릭 → 원 사건 딥링크(NAV-06). '캘린더 열기' → 전용 캘린더 뷰(후속: 전역 캘린더 승격은 conditionalGlobalItems의 기존 decision 항목과 함께 재검토).
- 기한(deadline) 항목은 적색 '기한' 플래그 — 로펌에서 기일·제출기한은 곧 액션이다.
- 빈 상태: 달력은 항상 렌더(빈 상태 없음), 선택일 일정 0건이면 "이 날 일정이 없습니다".

**W-04 뉴스레터·공지** (본문 하단 풀폭 — 액션 위젯 아래, 1슬롯 제한. 강조 1건(좌) + 목록(우) 가로 구성)

## 6. 데이터 계약 (실데이터 완전 연동, D-12)

**원칙**: 승인·태스크는 **단일 액션 인박스 소스**의 필터된 미리보기로 구현한다 — 위젯·사이드바 카운트·상단 배지·전용 뷰 간 건수 불일치를 원천 차단.

신규 API (apps/api, 기존 세션·권한 컨텍스트(ctx allow/denied/review) 규약 준수):
```
GET  /home/action-inbox?type=approval|task&role=…
     → { items: [{ id, type, subtype, title, matter_ref?, requester?,
          due_at?, risk_tier, allowed_actions[] }], counts: { approval, task_late, task_today } }
POST /home/action-inbox/{id}/decision   body: { action: approve|reject|complete, reason? }
     → 감사 로그 필수, 권한 재검증, 멱등
GET  /home/agenda?from&to
     → { events: [{ id, kind: hearing|deadline|meeting|external|absence,
          title, starts_at, ends_at?, location?, matter_ref? }] }
GET  /home/feed?tab=notice|news|newsletter
     → { entries: [{ id, source, title, body_preview, published_at,
          pinned_until?, audience? }] }
```
백엔드 집계 소스 (Stage 0에서 실제 라우트 인벤토리 후 확정 — 아래는 [직접 확인]된 웹 fetcher 기준 추정):
- 승인: People 요청함(HRX approvals: 휴가·비용·증명서·근무기록), Matter 결재(matter-approvals), AI 검토 큐(fetchAiReviewQueue)
- 태스크: Matter 할 일(matter-tasks 계열)
- 아젠다: matter-calendar + 외부 일정 + 부재
- 피드: People 공지(people-notices), 뉴스 커넥터(O-01 확정), O-02 뉴스레터 컬렉션

**뉴스 커넥터 스펙 (O-01 확정, 2026-07-07)** — 소스 4개: **블로터(bloter.net), 법률신문(lawtimes.co.kr), 딜사이트(dealsite.co.kr), 인베스트조선(investchosun.com)**
- 수집: 소스별 RSS/공식 피드 우선. 피드가 없으면 제목·링크·발행시각 수준의 최소 수집만 하고, **본문 전문 저장 금지**(저작권) — 클릭 시 원문 링크아웃(새 탭).
- 표시: `entries.source`에 매체명 칩 표기, 발행시각 역순 통합 정렬, 소스별 필터는 v1.1.
- 장애 격리: 한 소스 수집 실패가 탭 전체를 죽이지 않게 소스별 독립 fetch + 부분 성공 렌더. 전 소스 실패 시 빈 상태 "뉴스 피드를 불러오지 못했습니다 · 다시 시도".
- 갱신 주기: 서버측 캐시 15~30분(실시간 불필요), 위젯은 캐시 응답만 소비.

미존재 백엔드가 확인되면: 계약(스키마·빈상태·권한)을 먼저 고정 → 해당 위젯은 계약 기반 빈 상태로 릴리스 게이트 통과 가능 여부를 오너에게 보고 후 결정(단, D-12가 원칙이므로 기본은 구현).

## 7. Stage 분해 (Codex 실행 단위)

각 Stage는 독립 커밋 가능 단위이며, `npm test`·`npm run build` 그린 + 명시 게이트 통과 후 다음 Stage로. 커밋은 ui-workstream-conventions의 quiet-window·pathspec 규칙 준수.

**Stage 1 — 내비게이션 불변식** (게이트: 불변식 자동 테스트 그린)

## 9. 리스크·후속 트랙 (리서치 공백 반영)

1. **반응형/좁은 창 축소 규칙 미정** — 데스크톱 창 축소 시 우측 레일 접힘 규칙을 Stage 2에서 최소 정의(레일→본문 하단 스택), 본격 반응형은 후속.
2. **역할별 기본 위젯 세트** — v1은 권한 게이팅(W-01, 회사 현황)만. 역할 프리셋(변호사/스태프/관리자)은 v2 개인화와 함께.
3. **커맨드 팔레트(Cmd+K)** — 리서치 공백. 전역 검색이 이미 있으므로 후속 트랙으로 등록만.
4. **대량 승인자 시나리오** — 위젯만으로 부족(안티패턴 #12). home-requests 전용 뷰에 상태별 목록+일괄 승인을 포함하는 것은 v1.1로.
5. **전역 캘린더 승격 여부** — `conditionalGlobalItems`의 기존 decision 항목. W-03 사용 데이터를 보고 재결정.
6. **리서치 확증편향** — 성공 사례 위주 수집이었음. §8 지표로 출시 후 실증 검증(개편 실패·롤백 사례 부재를 지표로 보완).
7. **CTI(실데이터 주입 계획)와의 일정 간섭** — §6 신규 API는 CTI 컷오버 윈도우와 충돌하지 않게 Stage 3 착수 전 CTI 상태 확인.
