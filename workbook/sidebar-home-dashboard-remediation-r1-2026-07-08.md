## WP-1 실소스 집계 wiring — blocker (#1, #16, 연계 #21)

`/home/action-inbox`·`/home/agenda`·`/home/feed`를 시드가 아닌 실소스 집계로 전환한다.

1. 승인: HRX 요청함(휴가·비용·증명서·근무기록·커스텀·강제) + Matter 결재 + AI 검토 큐 → `type=approval`. **결재선 기준 '내가 결재할 차례' 서버 필터**와 `role`/사용자 컨텍스트 처리 구현 (#16).
2. 태스크: Matter 할 일(assignee=me & open) → `type=task`, `due_at` 필수.
3. 아젠다: matter-calendar + 외부 일정 + 부재 → kind 매핑(hearing/deadline/meeting/external/absence).
4. 피드: people-notices(notice 탭) + 뉴스 커넥터(기존 구현 유지) + Vault 태그 컬렉션(newsletter 탭, O-02 기본값).
5. 기존 계약(스키마·에러·감사·멱등·ctx fail-closed)은 변경 금지 — 집계 소스만 바꾼다. Stage 0 인벤토리 문서의 API 매핑 표를 갱신하라.
6. 게이트: 시드 없는 런타임 + 실소스 픽스처로 각 타입 ≥1건이 반환되는 API 테스트. 소스 하나 장애 시 부분 성공 응답 테스트.

## WP-2 전용 뷰 4종 + 리다이렉트 맥락 복원 — blocker (#4, #5, #10, #11, #6 일부)

1. `home-messages / home-requests / home-esign / home-company`를 HomeSurface(또는 형제 컴포넌트)에서 **실제 별도 화면**으로 렌더한다 — 현재는 전 섹션이 대시보드를 그대로 렌더.
2. `redirectedFrom`을 소비해 §4.2 표의 탭·유형 필터를 복원한다: messages(전송/자동화/템플릿/공지/Matter 대화 탭), requests(받은/보낸 탭 + 휴가·비용·증명서·근무기록·커스텀·강제 필터), esign(전송/템플릿/상태/설정 탭), reports-*(회사 현황 하위 탭).
3. home-requests에는 상태별 목록을 포함한다(일괄 승인·연속 처리는 v1.1 유지 — 이번 범위 아님).
4. home-company: 권한·감사 요약(구 home-audit-panel)을 이 화면으로 **복원**하고(#6), 데드 코드(buildApprovalRows/buildTodoRows)를 제거한다.
5. 게이트: 구 URL(예: `view=requests#requests-leave`) 진입 시 해당 탭·필터가 활성화되는 렌더 테스트.

## WP-3 메시지 소스 + 스레드 열람 — blocker (#3, #21 메시지분)

1. `utilityMessageItems` 하드코딩 빈 배열을 실소스로 교체(WP-1의 인박스 또는 Matter 대화/People 메시지 소스와 배선).
2. home-messages 화면(WP-2)에서 스레드 열람 시 unread 감소 — NAV-04 감소 규칙을 '드로어 수동 읽음 처리'에서 '스레드 열람'으로 이행(수동 처리 버튼은 유지 가능).
3. 사이드바 '메시지 (n)' 카운트 표시(#1의 사이드바분), 드로어에 실제 항목 목록.

## WP-4 O-03 권한 게이트 — blocker (#2)

1. 사이드바 노출 + 라우트 접근 + 콘텐츠 렌더 3층 모두에서 회사 현황을 관리자 role로 게이트(비인가 접근 시 home-dashboard로 폴백 + 안내). role 판정은 세션 컨텍스트에서 파생, 매핑은 상수 분리.
2. 게이트: 관리자/비관리자 렌더 테스트.

## WP-5 위젯 내부 규칙 — major (#7, #8, #12, #13, #14, #23~31)

- W-01: 받은/보낸 탭(#10, WP-2와 공유), 오래된 순 정렬 + 미리보기 4건(#23), 빈 상태 문구 "처리할 승인이 없습니다 — 모두 완료했습니다"(#30).
- W-02: 지연(D+n 적색)→오늘(주황)→임박 정렬·강조(#12) — risk_tier 배지를 마감 기반 표기로 교체, 헤더 "지연 n · 오늘 n"(#24), 체크박스 UI + 태스크 포커스 딥링크(#29), 온보딩 CTA 분기(#31), 미리보기 5건.
- W-03: 일자별 일정 점(일반=녹색, 기한=적색) + 일요일 적색(#8), 월 전환 ‹ › 버튼(#25), 기한 적색 플래그·'캘린더 열기'(#27).
- W-04: 읽기 패널 오버레이(#13), 탭 라벨 "사내 공지", 재시도 동작(#28).
- 공통: 5개 위젯 카드 우상단 '전체 보기 →' 앵커(Home 축 내 라우트, NAV-06/#14), 히어로 "오늘 처리할 항목 n건" = 인박스 counts 합계(#26).
- **실행 취소 실동작화(#7)**: 서버 결정 철회 엔드포인트(결정 후 짧은 창 내, 감사 로그에 철회 기록) + 클라이언트 5초 타이머. 서버 변경 없이 클라이언트 지연 커밋(5초 후 POST) 방식을 택해도 좋다 — 택한 방식을 보고에 명시.

## 실행·게이트 규칙

1. WP 순서: **WP-1 → WP-2 → WP-3 → WP-4**(blocker 우선, 상호 의존 순) → WP-5 → WP-6 → WP-7 → WP-8. WP-4는 독립적이므로 병렬 선행 가능.
2. 각 WP = 독립 커밋 단위. 게이트: 해당 WP 게이트 + `npm test`·`npm run build` 그린 + ui-regression 갱신(갱신 사유를 커밋 메시지에).
3. blocker 4개(WP-1~4) 완료 시점에 중간 보고 1회 — 이때 재검수를 요청하라.
4. 전 WP 완료 후: Stage 7 게이트의 '오너 확인' 항목을 위한 검수 패킷(변경 요약 + 스크린샷 + [직접 재실행] 표)을 작성하고 오너 재가를 기다린다. **오너 확인 기록 없이 "게이트 종결" 주장 금지** (#9 재발 방지).
5. 보고는 [직접 재실행](명령·종료코드)과 미검증을 구분 표기.
