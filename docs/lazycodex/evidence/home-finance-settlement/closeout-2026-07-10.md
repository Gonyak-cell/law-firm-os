## 권한·데이터 경계

- 실제 API 서명 세션은 명시적 `scopes` 배열이 있으면 재무 API에서 다시 검사한다.
- 테스트용 기존 permission context에 scopes 배열이 없을 때만 이전 fixture 호환을 유지한다.
- denied/review 응답은 금액·건수·고객명 없이 반환되고 감사 이벤트에 raw payload나 credential material을 남기지 않는다.
- 회계 CSV는 `finance.export`가 없으면 UI에서 렌더하지 않고 API도 403으로 차단한다.
- 고객별 집계는 canonical ClientGroup을 우선하고 미연결 금액을 별도 행으로 보존한다.
- 통화 환산은 하지 않으며 통화별 합계를 분리한다.

## AI slop 및 시각 QA

재무 화면 신규 구현에서는 강한/no-verify AI slop 신호를 확인하지 못했다. 실제 브라우저 대표 화면과 package 필수 9장 및 Matter 메뉴 보조 화면을 수동 확인했고, 메뉴 위계·표 대비·수평 오버플로·denied 상태·Matter 메뉴 제거가 정상이다.

`sloplint --changed`는 저장소의 기존 dirty `apps/web/src/styles.css`와 별도 durable-data 문서에서 weak 54건을 보고했다. 유형은 기존 장식 효과, 배경 명명, 모션, 고정 다크 테마, 문서 header 목록이며 이번 Home 재무 WP가 추가한 강한/no-verify 신호는 아니다. 이 closeout은 해당 기존 변경을 수정하거나 소유권을 주장하지 않는다.
